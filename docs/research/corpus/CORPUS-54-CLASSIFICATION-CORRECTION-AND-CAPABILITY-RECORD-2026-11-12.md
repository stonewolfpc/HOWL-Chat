## 4. Qualification 1 — Type N says nothing about what an item measures

`CORPUS-53` §5 and `CORPUS-50` O-8 both slid from "cannot distinguish memory" to "is a restraint test". The owner's correction is right and is adopted:

> A Type N classification establishes only that the item **cannot distinguish memory-present from memory-absent behaviour** under the pass-set test. It does **not** establish what the item measures.

**Required reporting language from here on:**

> Fourteen of sixteen items are non-diagnostic for memory under T0; fifteen of sixteen under T1 and T2. **Their other evaluation purposes must be reported separately.**

**What the fields document, and what they do not.** The corpus records purposes in item fields; it has not validated that any item achieves them.

| Field evidence | Units | Documented purpose (from the item, unvalidated) |
|---|---|---|
| `Reference: expected_abstention` + `Abstention: yes` | 4 (`F9-01`, `F9-02`, `F9-03`, `F9-05`) | abstention compliance |
| absence-shaped `Mandatory:` without `expected_abstention` | 8 | non-leakage of protected material |
| prose-absence naming the ignorant baseline (`F8-03`, `F9-03`) | 2 of the above | non-leakage, stated by the item itself |

**What no field establishes:** that a Type N pass demonstrates restraint rather than luck, indifference, or a reply that would have been produced anyway. Whether these items measure restraint is a **validity claim** requiring its own evidence — not something the P/N type confers.

## 5. Qualification 2 — `F6-02`: boundary versus enforcement

The owner-approved boundary is sound and is not in question. **Its coverage by the current item is a separate question, and the current item does not enforce all of it.** Reconciling the two:

| Owner boundary element | Enforced today? | By which field | Note |
|---|---|---|---|
| Aversion preserved, without recital | **Partly** | `Mandatory:` "the song is not pushed" (unnamed actor) + `R-1` | actor ambiguity: who pushes |
| Must not contradict or reverse | **No** | — | no scored field covers reversal |
| Must not act against it | **No** | — | endorsement is unscored |
| Must not invent a reason | **Yes** | `Prohibited:` "inventing the bad year" | the one firm enforcement |
| Supported explanation permitted | **Only by default** | `Over-exposure:` "explaining why…" is **unscored** — `M-2` does not name `F6-02` | permitted because the boundary is inert, not because it was designed so |
| No denial / neutralisation | **No** | — | minimisation is unscored |
| Alternative wording acceptable | Yes (structural) | `Variation:` "changing the subject; asking" | — |

**So, stated precisely:**

1. `F6-02`'s intended behaviour is a **valid restraint objective**.
2. `F6-02` **is not a memory diagnostic** — Type N at every tier.
3. The **existing item does not enforce** every element of that objective: three elements have no scored field, and one is permitted only through an unscored boundary.
4. The **proposed repair** addresses those gaps, but it is **unapplied**, so complete coverage must not be claimed before it is reviewed and authorised.

This is the `CORPUS-39` coverage audit, unchanged; `CORPUS-54` adds only the separation of "the objective is right" from "the item enforces it".
