## 3. Capability contract and ownership

One contract, one owner: `internal/audio/capability`.

A `Record` is one task/provider/model with six dimensions and one grade:

- provider availability, model availability, projector compatibility, runtime/build support, task support, hardware eligibility — each `available` / `unavailable` / `unknown` / `not_applicable`, each carrying its evidence or blocker;
- verification grade — `unverified` / `implementation` / `end_to_end`.

Tasks: `file_transcription`, `streaming_transcription`, `audio_understanding`, `realtime_conversation`, `speech_synthesis`.

The contract extends existing infrastructure rather than replacing it. Records are built from `types.ASRModelRegistry` and `types.ModelRegistry.TTSModels`, using the pipeline's own model-path functions (`audio.ASRModelPathFor`, `audio.TTSModelPathFor`) and the same registry that the resolver and planner read. There is no second model manager, no second resource manager, and no second provider framework.

Selection rules implemented in `capability.Select` / `AutoSelect` / `Fallbacks`:

- explicit selection is honoured exactly, or refused with every blocker; it is never replaced by a different provider;
- automatic selection considers only selectable records, prefers verified then implemented then local, and never crosses tasks;
- `Fallbacks` returns only same-task, same-locality providers, so a local failure cannot silently become a remote call;
- an `unknown` dimension blocks selection rather than rounding up to support.

Consumers: `Pipeline.Initialize` (explicit engine validation and automatic engine filtering), `App.GetAudioStatus` (the `capabilities` field the settings UI renders), and the tests.

## 4. DEBT-T1 — capability inferred from filename

**Before:** `app-model.go` set `HasVision = true` whenever `findMMProj` returned any file. An audio projector and a vision projector share the `mmproj-*.gguf` naming family, so an audio model would have been reported as vision-capable.

**Change:** `gguf.InspectProjector` reads the projector's own metadata (`clip.has_vision_encoder`, `clip.has_audio_encoder`, and the `clip.vision.*` / `clip.audio.*` key spaces) and classifies it as `vision`, `audio`, `hybrid`, or `unknown`. `HasVision` is true only for `vision`/`hybrid`; the profile also records `HasAudioInput` and `ProjectorKind`. An unreadable or undeclared projector stays `unknown` and vision is disabled, which is a fail-closed choice, not a support claim. The image-input error now names the projector's declaration instead of claiming an mmproj file implies vision.

**Regressions:** `TestInspectProjectorAudioFileDoesNotEnableVision` and `TestInspectProjectorVisionFileKeepsVision` build real minimal GGUF files; `TestClassifyProjectorMetadata` covers flags, key spaces, explicit-false veto, and empty metadata.

**Not changed:** the projector is still passed to `llama-server` at spawn, and the runtime still negotiates whether it accepts images.

## 5. DEBT-T3 — registry, resolver, status, UI disagreement

**Before:** the resolver hardcoded three Whisper files; the registry advertised Qwen ASR entries; the settings UI offered `whisper-medium`, `whisper-large` and `qwen-asr`, which the resolver rejected (`whisper-large` was not even a registry identity, `qwen-asr` did not exist); status reported only booleans.

**Change:**

- `approvedASRModels` is now derived from `types.ASRModelRegistry` (`Local && ApprovedLocal && LocalFile != ""`), so the resolver cannot disagree with the registry about what may be loaded locally.
- every ASR entry declares `Runtime`, `Local`, `ApprovedLocal`, `LocalFile`, `Verification`; every entry's `Verification` is a valid grade.
- the settings UI lists exactly the registry identities plus `auto`; the obsolete and non-existent options are removed.
- `GetAudioStatus` carries `capabilities`, built from the same contract, and the UI renders availability and the first blocker from it instead of guessing.
- the remote Qwen entries are now honestly labelled as DashScope API providers with no local size, VRAM or CPU claim, and are never recommended for automatic local use.
- explicit engine selection reaches the pipeline through `Settings.ASREngine` / `TTSEngine` → `PipelineConfig`, and a blocked explicit engine fails the capability with its blockers rather than falling back.

**Regressions:** `TestResolverApprovedSetDerivesFromRegistry`, `TestSettingsUIOffersOnlyRegistryASREngines`, `TestAutomaticASRStaysLocalAndAdmitted`, `TestExplicitASRIsHonouredOrRefused`, `TestExplicitASRWithBlockedDimensionsIsRefused`, `TestExplicitTTSIsHonouredOrRefused`, `app_audio_capability_test.go`.

## 6. DEBT-T2 — declared-but-unsupported streaming

`SupportsStreaming` is now false for every ASR entry: Whisper, both DashScope Qwen entries, and the local Qwen candidate. Whisper's `TranscribeStream`, the DashScope client's `TranscribeStream`, and the fallback chain all return "not supported", so no registry entry may advertise the mode.

The planner now returns no ASR candidates when streaming is required, because no adapter streams. `TestBuildSelectionPlanTinyTier` was updated to assert that empty plan (it previously asserted a streaming model that could not stream), and `TestASRRegistryStreamingMatchesAdapters` fails if a future registry edit reintroduces a declaration without an adapter. The capability contract reports every streaming record as unavailable with the adapter reason.

## 8. Existing functionality preserved

- Whisper remains an independent local ASR provider, registered first-class in the loader and the automatic plan; its lifecycle, limiter, concurrency, cancellation, temp-file cleanup and model-not-found behaviour are untouched. The Qwen adapter does not replace or wrap it.
- `Pipeline` still owns one recognizer/chain per generation; the manager still owns generations, leases, operations and bounds shutdown. The Qwen adapter is one more recognizer behind that contract, not a parallel manager.
- The llama-server ASR process is owned by its recognizer: startup failure is a named model-load failure, cancellation aborts a request, and `Release` kills and waits for the child before clearing initialized state.
- Ordinary text chat was not modified. The only chat-adjacent change is the image-input error text in `app-prompt.go`; no request construction, streaming, history or prompt assembly changed.
- Vision behaviour: a vision projector still enables image input, now because its metadata says so.
- TTS engines are unchanged; explicit TTS selection is validated against the registry and otherwise passes through.
