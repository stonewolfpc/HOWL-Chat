## 1. Purpose

CL1 asks one narrow question:

> When an imported file is transcribed, must the binding copy the source into its own per-transcription temporary directory, or may the provider read the imported source path directly?

The decision controls:

- where provider-generated sidecar files are written;
- whether the bytes validated are the bytes later transcribed;
- how source mutation during copying is handled;
- who owns cleanup and how cleanup is contained; and
- whether IR1 can be implemented.

It does not decide CL2 chunk order, CL3 `fmt ` handling, MEAS1 measurement, or implementation authorization.

## 3. Exact choice

### Option A — Bounded copy into binding-owned temp, then validate the copy (recommended)

**Rule.** For an imported file, after local-path and regular-file guards, open the source, create a binding-owned per-transcription temp directory, copy the source through a bounded reader into `input.wav` there, close the copy, validate the copied bytes, acquire the manager lease, transcribe the temp path, and remove the entire temp directory on every exit path.

**Required order.**

1. Reject empty, relative, non-local, scheme-bearing, or non-file inputs before opening. The design’s local-path guard remains controlling; `blob:` must never reach `os.Stat`.
2. `os.Open` the source and `Fstat` the opened handle. Require a regular file. Do not rely only on a prior path `Stat`.
3. Reject a source whose opened size exceeds `MaxImportedWAVBytes` before copying.
4. Create `os.MkdirTemp("", "howl-asr-*")` and install a `defer os.RemoveAll(tempDir)` immediately.
5. Create `input.wav` with exclusive creation (`O_CREATE|O_EXCL`) inside that directory.
6. Copy from the already-opened source handle with a bounded reader, for example `io.CopyN(dst, src, MaxImportedWAVBytes+1)` or an equivalent `LimitReader` plus counted copy. If the copy reaches `MaxImportedWAVBytes+1`, fail as an over-limit import. Never use `os.ReadFile` or an unbounded `io.Copy`.
7. Close both handles. On any open, create, read, write, close, or bound failure, remove the partial temp directory and return a specific import/copy failure. Do not acquire a lease and do not call a provider.
8. Re-open the completed `input.wav` read-only and validate the copied bytes as canonical PCM WAV, including the byte cap and `MaxImportedDurationMs`, before acquiring a lease.
9. Acquire one operation and one lease only after validation succeeds; transcribe the temp `input.wav`.
10. Remove the entire binding-owned temp directory on success, error, cancellation, and panic-safe defer. The provider’s `input.wav.json` sidecar, if produced, is inside that directory and is removed with it.

**Bounded-copy requirement.** The bound is enforced twice: the opened source size is checked first, and the copy itself stops at the cap. A source that grows during the copy cannot cause an unbounded read; it causes an over-limit copy failure. The completed copy is also checked before validation.

**Post-copy validation.** Validation is authoritative on the copied file, not on the source path. The source is never passed to the canonical parser after the copy. The copied file is what is validated and later transcribed, so there is no validation-to-transcription path switch.

**Source mutation during copying.** Opening the source once removes the ordinary path-reopen race, but it is not an atomic snapshot and does not freeze the file’s contents. Another writer can truncate, overwrite, append, or replace the file while it is being read. The resulting copy may therefore be a torn or mixed byte stream rather than the content of the source at any single instant. This packet does **not** claim otherwise. The safety property is narrower and testable:

- the copy is bounded;
- the copied bytes are validated after copying;
- only a copy that passes validation is transcribed; and
- a source mutation that produces an invalid WAV is rejected before a lease or provider call.

A source mutation that still produces a valid canonical WAV yields a valid copy, but the copy may not equal any single source instant. Detecting that case would require an atomic snapshot or a lock, neither of which is established here. An advisory post-copy `Fstat` comparison of size and modification time may be recorded, but it is not proof of an atomic read and must not be presented as one.

**Partial-copy cleanup.** Partial files are never validated and never transcribed. Cleanup closes handles first and removes the exact `tempDir` created by the binding. If removal itself fails, the primary copy/import error remains primary; whether and how the cleanup failure is joined is IR2 and is unresolved in this revision.

**Cleanup containment.** Cleanup is `os.RemoveAll(tempDir)` for the exact directory returned by `os.MkdirTemp`, not a user path and not a path assembled from the source. The binding must not call `cleanupTempFile` on the source, must not remove the source directory, and must not delete a sidecar by a source-derived path. Containment depends on the provider writing its sidecar next to the temp input, which the current recognizer behavior supports by deriving `<input>.json` from the input path; the provider’s exact write behavior remains source-derived, not independently verified in this packet.

This is not a claim that CL1 approval alone implements the copy.

### Option B — Validate and use the source path in place

**Rule.** Validate the imported source and pass its path directly to the provider; create a binding-owned temp directory only for recorded/base64 requests.

**Technical consequences.**

- Avoids one copy and duplicate temporary storage.
- The provider may write `<source>.json` beside the user’s imported file because the whisper path derives the sidecar from the input path (`recognizer.go:300-305`).
- `cleanupTempFile` only deletes inside the recognizer’s lifetime directory (`recognizer.go:384-392`), so it cannot clean a sidecar beside the source.
- The source can be replaced, truncated, or removed after validation and before or during transcription, creating a validation-to-use gap.
- A read-only source or read-only source directory may fail at provider time after successful validation.
- A source inside a user-managed directory becomes part of the provider’s working area.

**Affected tests.** T4, T5b, and L4 would need new rules for external sidecars and source mutation; T5 remains unchanged; T3 remains the parser test.

**Dependencies.** IR1 would be rejected or deferred. CL3 still controls `fmt ` handling.

**What remains unimplemented if rejected or deferred.** Binding-owned copy behavior is absent, and the owner must separately specify source-sidecar cleanup, source-mutation handling, and read-only-source policy.

## 4. Why Option A is recommended

**Recommend Option A: bounded copy into the binding-owned per-transcription temp directory.**

The design already assigns per-transcription directory ownership and sidecar cleanup to the binding (`docs/asr-repair-design.md:799-812`). Passing the source directly conflicts with that ownership model: the provider’s JSON sidecar follows the input path, and the recognizer’s cleanup function does not delete files outside its own lifetime directory. Copying keeps validation, transcription, and cleanup on one controlled path.

The copy is not recommended as an unbounded convenience. It must be bounded at `MaxImportedWAVBytes`, must validate the copied bytes, must remove partial output, and must not claim atomic source snapshotting. Those constraints are part of the proposal, not implementation details left to the implementer.

## 5. Proposed CL1 register wording

> **CL1 — Imported-file copying — PROPOSED, NOT APPROVED**
>
> For imported transcription, copy the source into the binding-owned per-transcription temporary directory as `input.wav` before canonical WAV validation and before acquiring a manager lease. Open the source once and require a regular file. Reject a source larger than `MaxImportedWAVBytes` before copying, and enforce the same cap during the copy. Never use an unbounded whole-file read. On any copy failure, close handles, remove the partial binding-owned directory, and return a specific import/copy failure without acquiring a lease or calling a provider.
>
> Validate the completed copy, not the source path. The source is never passed to the provider. A source mutation during copying may produce a torn copy; the binding does not claim an atomic snapshot. A copy that fails canonical validation is rejected before a lease. A copy that passes validation is the exact byte sequence later transcribed.
>
> The source remains untouched. The binding owns the copied file, the provider’s `input.wav.json` sidecar, and the temporary directory. Cleanup removes only the exact directory created by the binding, on success, error, cancellation, and panic-safe defer. Preserve the primary error when cleanup also fails, consistent with IR2 if and only if IR2 is separately resolved and adopted.
>
> This decision does not change `MaxImportedDurationMs = 600000` or `MaxImportedWAVBytes = 19,200,044`; does not decide CL2 chunk order or CL3 `fmt ` handling; does not approve IR1–IR6; does not close MEAS1 or T6; and does not authorize implementation, build, runtime, or measurement.

## 7. Review questions

1. Does the proposed order satisfy the design’s “validated before a manager lease” requirement while keeping copy failure pre-lease?
2. Is the bounded-copy rule sufficient when the source grows or is truncated during copying?
3. Is post-copy validation enough without claiming an atomic source snapshot, or does the owner require an explicit lock/snapshot policy?
4. Does cleanup containment correctly exclude the source and source directory on every path?
5. Are partial-copy cleanup and cleanup-failure aggregation correctly separated from transcription failure?
6. Does CL1 avoid deciding CL2, CL3, IR2, MEAS1, or implementation authorization by implication? It should.
