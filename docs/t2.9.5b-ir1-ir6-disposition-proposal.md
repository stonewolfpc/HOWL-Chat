## 4. Consequence detail

### IR1 — Copy imported WAV

IR1 is not independent of CL1. If CL1 selects Option A, IR1 supplies the implementation rule. If CL1 rejects copy, IR1 must be rejected or deferred; adopting IR1 without CL1 would bypass the ownership decision.

The copy is bounded, validates the copied bytes, removes partial output, and contains cleanup to the exact binding-owned directory. It does not claim an atomic source snapshot; a source mutation during copying may produce a torn copy, which post-copy validation either rejects or treats as the exact bytes later transcribed.

**Affected tests.** T4 establishes temp-directory and sidecar absence on success/error/cancellation/panic. T5b establishes the imported-file caps and pre-provider rejection. L4 establishes no lease/pipeline call on copy/setup failure. T5 establishes the legacy path guard remains intact.

**If rejected or deferred:** no copy is implemented; the source path reaches the provider directly. The owner must define external-sidecar cleanup, source mutation, read-only-source behavior, and the validation-to-use window elsewhere.

### IR2 — Join cleanup failure with the primary error: unresolved

**Go version.** `go.mod:3` declares Go 1.23.8. `errors.Join` exists in that language version and is already used by the manager and pipeline for cleanup aggregation.

**What `errors.Join` does preserve.** A joined error implements multi-error unwrapping; `errors.Is` and `errors.As` can discover the joined members. For a direct `*types.AudioError` member, `errors.As` can recover it. This is a Go-level property, not a frontend property.

**What it does not preserve.**

- `types.AudioError` has a `Cause` field but no `Unwrap()` method. A cause stored only in `Cause` is not traversable by `errors.Is`/`errors.As`; joining the outer `AudioError` does not expose its cause.
- `IsRecoverable` uses a direct type assertion, not `errors.As`; a joined error is not itself `*AudioError`.
- `TranscribeAudio` logs a fixed `errors.ASRTranscribeFail` code and returns the original error. The log code is not selected from the audio error.
- The generated Wails binding returns the Promise; the frontend catch concatenates the rejection into a string. No typed classification is observed at the frontend.
- The Wails runtime’s error serialization is not in this repository, so any structured code survival is unestablished.

**Therefore the intended claim — that `errors.Join` preserves the primary frontend error classification — is not established.** It may preserve a Go-level error member, but there is no observed frontend classification contract to preserve. IR2 is marked **DEFER — UNRESOLVED**, not approved.

**If a future decision wants Go-only aggregation:** that is a narrower rule and must be stated separately; it must not be described as preserving a frontend classification. **If rejected:** cleanup failure remains unreported, separately logged, or hidden by the primary error.

### IR3 — Either-order chunk acceptance

IR3 is meaningful only if CL2 selects Option B. Under CL2 Option A, `data` before `fmt ` is rejected and IR3 must not be implemented. This prevents an IR recommendation from silently overriding a CL decision.

**Affected tests.** T3 must include both orders if IR3 is adopted; T5b must exercise both at the guard; T4 must confirm cleanup on the additional paths. Under CL2-A, T3/T5b add the `data`-first rejection and T4 confirms cleanup on that rejection.

**If deferred:** the parser remains `fmt `-first; no additional order compatibility is claimed.

### IR4 — Extended `fmt ` acceptance

IR4 as written says to accept `fmt ` longer than 16 and ignore extra bytes. CL3 Revision 2 rejects that as a blind-ignore rule. IR4 is therefore **rejected as written**.

The replacement scope is CL3 Option A:

- 16-byte PCM `fmt` accepted;
- 18-byte PCM `fmt` accepted only with `cbSize == 0`;
- lengths below 16, above 18, and odd lengths rejected;
- `wFormatTag` other than 1 rejected, including `0xFFFE`;
- no extension tail is ignored.

**Affected tests.** T3 establishes the 16/18/longer/tag/odd/truncation matrix. T5b establishes the imported-file byte/duration caps and pre-provider rejection. T4 establishes cleanup on every rejection path.

**If CL3 selects exact-16 instead:** IR4 remains rejected; 18-byte files are rejected. **If CL3 is deferred:** IR4 remains unresolved and no extended-`fmt ` behavior is authorized.

### IR5 — Error-category names

**Exact existing mechanisms.**

| Mechanism | What it is | Relevance |
|---|---|---|
| `types.AudioErrorCode` | Integer code type in `internal/audio/types/interfaces.go:347-360` | Existing audio category surface |
| `types.ErrCodeFormatNotSupported` | Base code for unsupported format/status | Candidate for parser shape/format rejection |
| `types.ErrCodeModelNotFound`, `ErrCodeModelLoadFailed`, `ErrCodeTranscriptionFailed`, `ErrCodeTimeout`, `ErrCodeCancelled` | Other base codes | Existing surface; no new name needed for those cases |
| `types.AudioError` | Struct with `Code`, `Message`, `Cause`, `Recoverable` | Existing typed error; no `Unwrap` |
| `types.NewAudioError` | Constructor | Existing construction path |
| `asr.ErrCodeFormatNotSupported` and other `asr.ErrCode*` | Separate ASR namespace starting at 100 | Not automatically the parser’s base code; avoid import-cycle coupling |
| `asr.New...Error` constructors | Return `*types.AudioError` | ASR-specific construction |
| `errors.ASRTranscribeFail` via `a.logError` | Logging code at the binding | Not a returned audio category and not observed at the frontend |

**Recommendation.** Reject IR5’s new-public-name scope. Do not invent a new parser category. Use the existing `*types.AudioError` surface for parser shape/format failures where it maps cleanly; the strongest established mapping is `types.ErrCodeFormatNotSupported` for malformed/unsupported WAV shape. The mapping for copy I/O, byte-cap, and duration-cap failures is not established by the existing source and must not be guessed in this proposal.

**Affected tests.** T3/T5b should assert `errors.As` to `*types.AudioError` only where the implementation actually returns one, and assert the specific message/category the owner approves. Do not assert a frontend code, because none is observed.

**If rejected or deferred:** no new public names; existing codes/messages remain. A later requirement for a distinct public category requires a separate decision.

### IR6 — JavaScript unit-test harness versus MEAS1 harness

These are separate requirements.

**IR6: JavaScript unit-test harness.**

- `tests/e2e/package.json` is a Playwright E2E package; `tests/e2e/playwright.config.js` runs browser specs against the Wails dev server.
- No root `package.json` exists.
- `frontend/dist/js/wav-encode.js` and `app_audio_transport_test.go` are absent.
- The design says not to invent a JS runner or root package (`docs/asr-repair-design.md:1188-1193`).

**MEAS1: packaged measurement harness.** MEAS1 separately requires:

- an exact test-only frontend entry point path and source hash (`docs/t2.9.5b-meas1-measurement-plan.md:162-166`);
- every test-harness asset loaded by the packaged WebView and its hash (`:166`);
- the same generated binding function and request model used by production (`:169-179`);
- a packaged Wails application, not a browser-only harness or Go-only call (`:134`);
- a source-level comparison and build-fidelity rule (`:179`, `:226-231`);
- harness provenance in the evidence manifest (`:628`).

**Therefore:** deferring IR6 does **not** waive MEAS1’s harness prerequisite. MEAS1 remains blocked until its own harness path, assets, provenance, and hashes are identified and reviewed. The IR6 deferral concerns T1/T2 JavaScript-side unit coverage only.

**If deferred:** no new JS unit harness is created; T1/T2 JS-side unit coverage remains unclaimed; MEAS1 still requires its separate packaged harness. **If approved:** selecting a JS unit harness would expand T2.9.5B scope and is not recommended.

## 5. Recommended owner action

The owner may dispose of each IR independently. The recommended package is:

1. **CL1 Option A** and **IR1 approved**.
2. **CL2 Option A** and **IR3 rejected/deferred**.
3. **CL3 Option A** and **IR4 rejected as written; 16/18 rule adopted through CL3**.
4. **IR2 deferred/unresolved**.
5. **IR5 rejected as a new-name scope; limited reuse of existing typed mechanisms**.
6. **IR6 deferred for the JS unit harness; MEAS1 harness requirement preserved and not waived**.

This package avoids expanding T2.9.5B into a new error taxonomy or a new JavaScript unit-test harness, while preserving the copy, cleanup, chunk-order, and bounded `fmt ` behavior that the design and tests need. It does not close MEAS1 or T6.
