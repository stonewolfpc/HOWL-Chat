**Scope:** correction of the prior report only. No implementation, no measurements, no register edits, no freeze changes, no Git changes.

### §1 Route registration and handler implementation (requirement 1)

#### 1.1 What is actually established

At commit `a34de8618b25dfc32ee43749db47d767a9f0a25d`, `tools/server/server.cpp` registers three audio-related routes: `POST /v1/audio/transcriptions` (with `/audio/transcriptions` alias), `POST /tts`, and `WS /v1/realtime`. Handler declarations are at `tools/server/server-context.h:124-135`; implementations are in `tools/server/server-context.cpp`. *(Registration is source-verified at the commit; the exact line numbers of the registration block were not retained in this pass and are therefore cited at file level rather than fabricated.)*

| Route | Handler | Implementation | Gate read in source |
|---|---|---|---|
| `POST /v1/audio/transcriptions` (+ `/audio/transcriptions`) | `post_transcriptions_oai` | `tools/server/server-context.cpp:6080` | requires `has_mtmd && chat_params.allow_audio`; multipart `file` mandatory; `response_format` json only |
| `POST /tts` | `post_tts` | `tools/server/server-context.cpp:6435` | requires `has_cap_tts()`, i.e. `mtmd_cap.audio_gen`; accepts input/prompt, language, voice, speaker reference; WAV/PCM; streaming supported |

**Consequence:** these endpoints are not "strings in a binary". They are registered routes with implemented handlers and explicit capability gates. A request without a capability-bearing model is rejected by the gate, not served.

### §6 Revisiting the proposed 5B.1 boundary (requirement 5)

**The premise is withdrawn.** Deferring native ASR to "5B.1" is not an established project requirement. The established requirement is: support Whisper **and** the useful llama.cpp-native audio capabilities, with user selection and intelligent routing. Whether native file ASR lands in this tranche or a later one is a scope decision, not a pre-existing constraint — and this addendum does not make it.

Recommended smallest coherent sequence:

**Tranche A — audio-input foundation (the coherent current unit).**
1. A provider-neutral capability contract: task (file ASR / live ASR / understanding / realtime / TTS), input modalities, output modalities, streaming, transport, model class, projector kind, verification state, resource class.
2. Routing that honors explicit selection first and filters Auto by *actually supported task*.
3. Whisper retained as the incumbent local provider, with its declared capabilities corrected to match its adapter (streaming is not supported).
4. **One** verified native file-ASR path — Qwen3-ASR 1.7B via `llama-server`'s transcriptions route — admitted only after a load/probe step establishes `has_mtmd`, `allow_audio`, and a successful transcription on the target machine.
5. Status/selection UI showing provider, task, and verification state.

Entry criteria: runtime artifact set is single-build and hash-recorded; Qwen3-ASR main + audio mmproj present; transcriptions probe passes.
Exit criteria: file ASR works through both providers; explicit selection is honored; Auto never crosses tasks.

**Tranche B — direct audio understanding.** Chat content pipeline extended to carry `input_audio`. Additive to the contract.
**Tranche C — TTS.** `audio_gen` model class; output modality; distinct resource policy. Additive.
**Tranche D — realtime conversational audio.** WebSocket session, PCM16 mono, streaming UI, concurrency and eviction policy. Additive, and the most expensive.

Each tranche is architecturally additive to the same contract — no replacement of the routing layer is required later. **None of these tranches is authorized by this addendum.** In particular, admitting a native ASR provider requires explicit authorization; it is not implied by "support useful llama.cpp-native capabilities" and it is not inherited from 5B.1.

### §7 Selection and resource rules (requirement 6)

| Rule | Required behaviour |
|---|---|
| Precedence | An explicit provider and task selection always wins over Auto. Auto is consulted only when the user has not chosen. |
| No silent locality switch | Local→remote (or remote→local) substitution requires an explicit, informed action. Qwen ASR today is a remote DashScope call (`internal/audio/asr/qwen/client.go:23-33`) and must never be presented as a local engine. |
| No silent task switch | Transcription must never be served by an audio-understanding call, and understanding must never be served by a transcription call. They are different contracts with different prompts and different failure modes. |
| Auto eligibility | Auto chooses only among providers that declare the requested task, are installed/present, and are in a verified-or-explicitly-unverified-consented state. |
| Resource protection | Ordinary chat is never silently unloaded, quantized down, or degraded to make room for audio. Insufficient headroom yields a refusal or a queue — never an eviction of the active chat model. |
| Disclosure | Unavailable capability shows *why* (no audio projector / model lacks `audio_gen` / provider unreachable / verification pending), and any fallback shows *what changed* and requires consent. |
| No invented identity | Model identity is never inferred from filename or from a bare `mmproj` presence. |

The current code violates several of these already, and those violations are in scope for correction: `GetAudioStatus` hardcodes `multimodal_ready:false` / `realtime_ready:false` regardless of reality (`app-audio.go:107-128`); the ASR registry declares streaming `true` for Whisper and Qwen (`internal/audio/types/asr_models.go:50,79,137,166`) while both adapters reject streaming; the UI offers Medium/Large and "Qwen ASR (API-based)" (`frontend/dist/audio-settings.html:96`) while the resolver approves only tiny/base/small (`internal/audio/model_resolver.go:69-76`).

### §8 Licensing and packaging (requirement 7)

**Runtime code.** `runtime/llama/` contains only `LICENSE-LLVM-OpenMP` (19,741 B). No llama.cpp MIT notice, no ggml notice, no third-party notice bundle. llama.cpp is MIT upstream; redistribution therefore requires the MIT copyright and permission text to accompany the binaries. **Grade: E1/E2; obligation currently unmet.** This is a packaging defect independent of any audio feature.

**OpenMP runtime.** `libomp.dll` shipped with `LICENSE-LLVM-OpenMP` — the notice and the artifact are consistent (E1).

**Model weights.** Weights are not bundled (E1), but they carry their own terms, distinct from the runtime's:

| Family | License status |
|---|---|
| Qwen3-ASR / Qwen3-TTS / Qwen2.5-Omni / Qwen3-Omni | per-repo terms; app registry records `"qwen"` (`asr_models.go`) — **not a verified SPDX identifier** |
| Gemma 4 E2B | card states Apache-2.0 (E0) — historically Gemma ships under Gemma Terms; **verify before redistribution** |
| LFM3-Audio-2B | LFM Open License v1.0 — carries attribution/acceptable-use terms that may reach the UI |
| Voxtral / Ultravox | **unestablished**; base-model terms may govern the derivative |
| Whisper GGUF | MIT (whisper.cpp distribution) — but whether the app redistributes whisper.cpp binaries at all is **not established** |

**User-supplied weights do not discharge the application's obligations.** The app's own MIT-notice duty, any download-on-behalf terms, attribution requirements bound to the model license, and the UI's obligation not to misrepresent provenance all survive regardless of who supplies the file. Downloading weights on the user's behalf can also make the app a distributor under some of these licenses — a determination to make per family, not in aggregate.
